# 数据与隐私

简单说：数据留在你自己的 Home Assistant 里，不会上传到作者服务器；但为了工作，它必须和小米、你的 Home Assistant 通信。主动开启「AI 托管」时，语音文本还会发给你配置的 AI 接口。

## 文件都在哪

| 内容 | 位置 |
|---|---|
| 配置（规则、别名、HA 地址、轮询间隔、AI 设置） | `/data/config/config.yaml` |
| 小米登录凭据 | `/data/config/auth.json`、`/data/config/.mi.token` |
| 直连访问令牌 | `/data/config/.access_token` |
| 已处理消息的时间戳（去重用） | `/data/config/last_timestamp.json` |
| 运行日志 | `/data/logs/bridge.log`（轮转保留 2 MB × 4 份） |

升级加载项不会删除这些文件。

写盘用的是「先写临时文件再替换」，断电时旧文件还在。两个凭据文件不是跨文件事务，
如果出现身份不一致，启动时会拒绝这次混合登录并提示重新认证，而不是带着错乱的凭据跑。

## 语音指令怎么去重

桥接器先记下这条消息的时间戳、再执行动作。好处是重启后不会把同一条语音再执行一遍；
代价是如果当时 Home Assistant 执行失败，这条指令不会自动补执行。

去重文件损坏时桥接器会停下来，不会把旧语音当新指令执行。遇到这种情况检查文件或从备份恢复，
不要一删了之。

## 会发给谁

项目不会把数据上传到作者服务器；以下通信是运行所需，或由你主动开启：

| 数据 | 发给谁 | 什么时候 |
|---|---|---|
| 小米登录凭据、令牌 | 小米（`account.xiaomi.com`、`*.mina.mi.com`） | 登录、自动续期 |
| 设备列表、对话记录（含语音识别文本） | 小米（`*.mina.mi.com`） | 启动、轮询对话记录时 |
| TTS 回复文本 | 小米 | 开启语音反馈并回复时 |
| Home Assistant 地址、长期访问令牌、服务调用与实体列表 | 你填写的 Home Assistant 地址 | 配置测试、执行动作、读取实体时 |
| 语音文本 + 设备名称、实体 ID、状态、可用动作 | 仅当你开启「AI 托管」时，发给你配置的 AI 接口 | 规则没有匹配上时 |
| 规则、别名、配置 | 只留在 `/data` | — |

「AI 托管」默认关闭；不开就不会有任何 AI 接口请求。

## 谁能打开面板

- **侧边栏面板**：走 HAOS Ingress，用 Home Assistant 自己的登录，只有管理员能看到；
- **直连端口**：`http://<主机IP>:47521`，需要直连令牌，且是**明文 HTTP**。
  令牌和会话 Cookie 在局域网里是明文传输的，所以只在可信局域网用，别映射到公网。

## 哪些地方做了脱敏

- 界面上密码、Cookie、HA 令牌、AI 密钥一律打码；
- 读取配置的接口不会返回这些字段；
- 日志只提示令牌文件的位置，不打印令牌本身。

## 备份

`/data` 会随 Home Assistant 的备份一起备份，**备份文件里包含小米凭据、HA 令牌和直连令牌**。
请自己保管备份文件，不要公开分享。

怀疑泄露时：清除登录凭据、删除 `.access_token` 并重启加载项，然后重新登录。
删令牌文件会换一个新的直连令牌，旧的自然失效。
