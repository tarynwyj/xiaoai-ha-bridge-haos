# 使用指南

这篇讲四件事：怎么写语音规则、怎么建定时任务、多台音箱怎么分工、AI 托管怎么开。

## 意图规则

一条规则就是：**听到什么话 → 做什么动作 → 对哪些设备做**。

### 各字段的含义

| 字段 | 说明 |
|---|---|
| 规则名称 | 只用来在列表里区分规则，**不参与语音匹配**；不填就显示触发语句 |
| 触发语句 | 你实际会说的那句话，例如 `打开客厅灯`、`把空调调到{num}度` |
| 设备类型 | 灯光 / 开关 / 空调 / 场景 / 媒体 / 脚本 / 自动化 / 虚拟开关 |
| 操作 | 按设备类型给出，见下表 |
| 目标设备 | 复选框，可以勾多个；支持搜索、全选、清空 |
| 额外参数 | 按设备类型出现，例如亮度%、温度 |
| 回复 | 执行完小爱念的话，可留空 |
| 其他(JSON) | 直接并进动作的额外字段，日常用不到，写定时任务时才会用 |

### 每种设备类型能做什么

| 设备类型 | 可用的操作 | 额外参数 |
|---|---|---|
| 灯光 | 开 / 关 / 切换 | 亮度%（填 `{0}` 表示取语句里的数字） |
| 开关 | 开 / 关 / 切换 | — |
| 空调 | 开机 / 关机 / 调温 | 模式、温度（`{0}`）、延迟关（分钟，`{0}`） |
| 场景 | 执行 | — |
| 媒体 | 开 / 关 / 播放 / 暂停 | — |
| 脚本 | 执行 | — |
| 自动化 | 启用 / 禁用 | — |
| 虚拟开关 | 开 / 关 / 切换 | — |
### 匹配顺序

规则从上往下试，**第一条命中的生效**，后面的不再看。常用的规则放上面。

### 带数字的指令

语句里写 `{num}` 表示这里有个数字，动作里用 `{0}`、`{1}` 引用：

- 触发语句：`把空调调到{num}度`
- 设备类型：空调 → 操作：调温 → 温度填 `{0}`

说「把空调调到 26 度」，空调就设成 26 度。`{num}` 只匹配整数；「26.5 度」不会命中这条规则，需要小数时请改用整数温度。

### 一条规则控多台

目标设备是复选框：点一下勾上，再点一下取消，不用按 Ctrl。上面有搜索框、「全选」「清空」，
右侧会显示已选几台。设备列表在后台刷新时，已经勾上的不会丢。

### 保存

每条规则右侧有「保存」，只提交这一条；页面顶部的「保存全部」才一起提交所有改动。
改过但没保存的规则，标题旁边会显示「未保存」，保存成功后消失。收起规则不会丢掉未保存的改动。

### 先试再说

规则页顶部有个测试区：输入一句话，页面会显示命中哪条规则、准备执行什么；勾上「实际执行」
会真的调用一次 Home Assistant，注意别在测试时误开设备。

### 备份与迁移

规则页支持导出成 JSON、从 JSON 导入。换设备、换家庭前导出一份，之后导回去就行。

### 别名

「设备管理」页可以给 Home Assistant 实体起中文别名。设备列表、规则列表和定时任务里会优先显示别名，比实体 ID 好认。
别名也会参与「AI 托管」和定时任务的设备识别：说别名能对上设备。普通意图规则按触发语句匹配，目标设备是在列表里勾选的，不受别名影响。

## 定时任务

两条路，效果一样：对音箱说，或者在面板里建。

### 面板里建

定时任务页 →「新建定时任务」：

| 字段 | 说明 |
|---|---|
| 房间 | 先按房间筛设备；HA 不支持房间接口时这一项不显示 |
| 设备 | 复选框，可多选；切房间或搜索不会清掉已选 |
| 操作 | 按设备类型给出可执行操作 |
| 时间 | 24 小时制，时:分 |
| 重复方式 | 每天 / 工作日 / 周末 / 自定义星期 / 仅一次（指定日期） |

保存后会写进 Home Assistant，成为一条以 `xiaoai_bridge_` 开头的自动化。

### 直接对音箱说

| 怎么说 | 效果 |
|---|---|
| 每天早上七点半打开热水器 | 每天 07:30 |
| 每天晚上八点关掉客厅主灯 | 每天 20:00 |
| 每周一三五晚上九点打开客厅主灯 | 周一、周三、周五 21:00 |
| 工作日早上七点打开热水器 | 周一到周五 07:00 |
| 周末下午三点打开卧室窗帘 | 周六、周日 15:00 |
| 明天八点打开热水器 | 只有明天 08:00 |
| 后天八点打开热水器 | 只有后天 08:00 |
| 今晚十二点打开热水器 | 当天结束后的 00:00 |
| 十分钟后关掉客厅灯 / 半小时后关插座 / 两小时后关灯 | 一次性，按相对时间算 |
| 每天七点一刻打开热水器 | 07:15 |

「晚上十二点」会当成次日 00:00，「中午十二点」是 12:00。

设备名要说成 Home Assistant 里认得的名字，或者先给它起个别名。解析不出来时，
日志会写清楚缺什么，不会假装建成功。

### 建好之后

- **写在 Home Assistant 里**，所以桥接器没启动也会按时执行；
- 同一句话重复说不会堆出多条任务；
- 建完会回读一次 Home Assistant，只有真的加载了才显示为成功，否则列表标「HA 未加载」；
- 列表里能看到下次执行时间、最近触发时间和来源（语音 / 面板）；
- 可以**编辑**（覆盖同一条自动化，不会新建第二条）、**暂停 / 启用**、**清理已完成**；
- 一次性任务执行后标「已完成」，不会自动删除；到点时 HA 没在跑会标「已过期未执行」，
  改个时间重新安排即可；
- 日期、时间、执行记录都以 **Home Assistant 的时区**为准，和浏览器、加载项的时区无关。

## 多台小爱音箱

默认**监听账号下所有小爱设备**，对哪台说话都算数。桥接器会轮流读每台的对话记录，
谁说的话，回复就念在哪台，不会几台一起播。

只想听其中几台：小米账号页 →「接收语音的小爱音箱」→ 选「仅监听所选音箱」→ 勾选 → 保存 →
重启桥接器。几点说明：

- 「全部」模式下复选框全部勾选，且不能单独取消，要逐台选就先切到「仅监听所选」；
- 选「仅监听所选」时至少要勾一台，否则保存会被拒绝，空选择不会被当成监听全部；
- 选过但现在没被发现的音箱会保留勾选并标「当前未发现」；
- 如果设了范围却一台都没匹配上，桥接器会等着这些音箱，不会改去听你没选的设备，
  日志里会写清楚。

### 设备参数那张卡

「设备参数」里只有一组值：音箱型号、设备 DID、「TTS语音反馈」开关。它代表默认设备，
账号里加几台音箱也不会变成多张卡。管理「听哪几台」用上面的监听范围，不用这张卡。

## AI托管（可选）

高级设置里打开「AI托管」，选一个提供商（OpenAI、DeepSeek、硅基流动，或自填接口地址），
填密钥和模型名，保存。

打开后，当一句话没匹配上任何规则时，桥接器会把这句话发给这个接口，让它判断该做什么。
默认关闭。打开会带来额外的调用费用和一点延迟，语音文本也会发给你填的这个接口——
介意的话就别开。

## 高级设置里的其他项

- **轮询间隔**：高级设置里「轮询」卡片中的「间隔（秒）」，默认 2 秒，可设 1 到 60。
  调小反应更快、请求更多；调大省请求、反应变慢。
- **显示直连令牌**：查看直连端口要用的令牌，见 [安装与首次配置](install.md#备用入口直连端口)。
