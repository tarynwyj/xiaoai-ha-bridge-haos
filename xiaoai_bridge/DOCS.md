## 打开管理界面

**推荐：Home Assistant 侧边栏**
安装后左侧边栏会出现 **小爱语音桥接** 面板（HAOS Ingress）。它沿用 Home Assistant 自己的
登录认证，只有管理员可见，不需要额外令牌。

**直连端口（旧入口）**
`http://<HAOS 主机IP>:47521` 仍然保留，但从 1.0.10 起**必须输入直连访问令牌**：

- 令牌保存在容器内 `/data/config/.access_token`（随机 256 位，首次启动生成）；
- 查看方式：侧边栏面板 → **高级设置** 页 → **🔑 显示直连令牌**；该接口只接受来自 Supervisor
  的 Ingress 请求，直连会话拿不到；
- 出于安全考虑，附加组件日志**不打印令牌本身**，只提示令牌文件位置；
- 若 `/data` 只读或磁盘已满，令牌可能无法保存到文件；仍可从侧边栏面板的“高级设置”页
  获取本次运行的令牌，但重启后会变化。请恢复目录可写或释放空间；
- 想换令牌：删除 `.access_token` 文件后重启附加组件即可重新生成；
- 脚本调用可以不用 Cookie：`curl -H "Authorization: Bearer <令牌>" ...`；
  `X-Admin-Token: <令牌>` 是 Bearer 的等价备用通道（同样权限，不是更弱的模式）；
- 令牌在 `/data` 下，会随 Home Assistant 备份一起备份；怀疑泄露就删掉它并重启轮换；
- 直连端口是**明文 HTTP**：令牌与会话 Cookie 在局域网内明文传输（浏览器不能为 HTTP
  Cookie 启用 `Secure` 保护），**只建议在可信局域网使用**。跨网段/公网请走 Ingress 面板，
  不要把直连端口暴露到公网；直连登录每次签发独立会话，最长七天，点击「退出登录」会在服务端撤销，
  旧 Cookie 即使被复制也不能再次使用。加载项重启后，直连浏览器需要重新登录；
  此注销**不撤销**脚本持有的 Bearer 访问令牌，如怀疑该令牌泄露，仍需轮换 `.access_token`；
- 面板可见性由 `config.yaml` 的 `panel_admin: true` 保证（只有 HA 管理员能看到面板）。
  改成 `false` 会让任何 HA 用户都能打开面板并读到直连令牌，请勿随意修改。

> 升级后浏览器如果还停在旧页面，会看到「会话已失效，正在返回登录页」并自动刷新，属正常现象。

## 配置步骤

1. 打开管理界面（侧边栏面板，或直连端口登录后）。
2. **小米账号** 页有三个登录入口（1.0.12 起）：
   - **扫码登录（推荐）**：点「扫码登录」，用米家 App 扫描二维码；
   - **账号密码登录**：填账号密码 → 点「登录」。小米要求二次验证时，同一张卡片里会出现
     验证码面板：点「获取验证码」（60 秒冷却）→ 输入数字验证码 → 点「提交验证码」；
   - **高级选项：手动 Cookie 登录**（默认折叠）：粘贴浏览器 Cookie（至少含 `userId` 与
     `passToken`）→ 点「验证 Cookie」。同一张卡片下方还保留
     「兼容：粘贴浏览器跳转地址（可能因会话绑定返回 401，不推荐）」子块。
   > 账号密码 + 验证码、Cookie 两种流程已通过模拟回归测试，**真实小米账号兼容性仍待验证**，
   > 建议优先使用扫码登录。验证码一次有效 5 分钟、连续输错 5 次需重新登录。

3. **Home Assistant** 页填写地址与长期访问令牌，点「测试」：
   - 地址示例：`http://homeassistant.local:8123`（容器内访问宿主机的常见写法）；
   - 令牌获取：HA 左下角头像 → 个人资料 → 长期访问令牌 → 创建。
4. **意图规则** 页新增规则，保存（详见下节）。
5. 回到 **仪表盘** 页点「启动」，等 **实时日志** 出现「桥接器已启动」。
6. 对小爱说一句规则里的语句，在仪表盘确认「最近」与「指令执行」有变化。

## 意图规则怎么写

一条规则 = **规则名称（可选）** + **触发语句** + **一个动作** + **一组设备**：

| 字段 | 说明 | 示例 |
|---|---|---|
| 规则名称（可选） | 只用于界面展示和管理，**不参与语音匹配**；留空时列表标题显示触发语句 | `客厅灯组开灯` |
| 触发语句 | 匹配语音文本的模式；普通文字即精确包含，`{num}` 代表一个数字 | `打开客厅灯`、`把空调调到{num}度` |
| 设备类型 | 决定可选操作与额外参数 | 灯光 / 开关 / 空调 / 场景 / 媒体 / 脚本 / 自动化 / 虚拟开关 |
| 操作 | 要调用的 HA 服务 | 开 / 关 / 切换 / 调温 / 执行 … |
| 实体 ID | 目标实体，用复选框勾选（可多选，一条规则控多台设备）；支持搜索、全选、清空 | `light.ke_ting_deng` |
| 额外参数 | 依设备类型出现，如亮度%、温度、空调模式、延迟关闭 | 温度填 `{0}` 表示取语句里的数字 |
| 回复 | 执行后小爱念出的内容 | `好的` |
| 其他(JSON) | 直接合并进动作的其他参数（如定时任务） | `{"type":"schedule","schedule_time":"23:00:00"}` |

匹配规则：从上到下按顺序试，第一条命中的规则生效；`{num}` 会变成数字捕获组，动作里用
`{0}`、`{1}` 引用捕获内容并自动转成数字（能转 int/float 就转）。

**示例：把空调调到指定温度**

- 触发语句：`把空调调到{num}度`
- 设备类型：空调 → 操作：调温 → 实体：`climate.wo_shi_kong_diao`
- 温度：`{0}`

说「把空调调到 26 度」会调用 `climate.set_temperature`，`temperature=26`。

**示例：一句关掉三盏灯**

- 触发语句：`全部关灯`
- 设备类型：灯光 → 操作：关
- 实体：按住 Ctrl 选中客厅、餐厅、走廊三个 `light.*`

**设备多选**：实体 ID 是复选框列表，点一下即勾选/取消，不需要按 Ctrl；列表上方可以按名称或
`entity_id` 搜索，也有「全选」「清空」，右侧显示「已选择 N 个设备」。设备列表异步刷新时
不会清掉已勾选的设备（HA 暂时离线也会保留原选择）。

**单条保存与「未保存」标识**：每条规则右侧有 `编辑/收起 | 保存 | 删除`。点「保存」只提交
**这一条**（其他规则里没保存的修改不会被一起提交）；点页面顶部「保存全部」才会统一提交所有
修改。改过的规则标题会显示「未保存」，保存成功后消失；收起规则不会丢失未保存的修改。

**规则名称 vs 触发语句**：规则名称只是给人看的，语音匹配始终使用「触发语句」（底层仍是
`pattern`，`{num}` 等写法不变）。没有填规则名称的旧规则会直接显示触发语句，不需要迁移。

**先测再说**：规则页顶部测试区输入一句话 → 界面会显示是否匹配、匹配到哪条、将要执行的
JSON（勾选执行时还会真的调用一次 HA）。

**导入导出**：规则页支持导出成 JSON 备份、从 JSON 导入，方便迁移或在多套规则间切换。

## 语音回复、别名与定时任务

- **语音回复（TTS）**：规则里的「回复」会通过小爱音箱念出来；不想要回复可留空或关掉配置里的
  `tts_reply`。
- **设备别名**：**设备管理** 页给 HA 实体起中文别名，规则里显示更直观。
- **定时任务（持久化）**：在规则「其他(JSON)」里加
  `{"type":"schedule","schedule_time":"23:00:00","schedule_days":[1,2,3,4,5,6,7]}`，
  说对应语句时会在 HA 里创建一条 `xiaoai_bridge_*` 自动化；已创建的会列在 **定时任务** 页。
  此类 HA 自动化不依赖桥接器一直运行。
- **延迟动作（仅当前运行周期）**：`delay_minutes` 使用桥接器进程内任务执行，不是 HA
  自动化，也不会跨桥接器重启恢复。桥接器停止或加载项重启时，未到期的延迟任务会被取消并记录日志；
  **需要在设备重启后仍执行的任务，请使用上面的 HA 定时自动化**。
- **AI 托管（可选）**：配置里开启 `ai_mode` 并填写 OpenAI 兼容的 `api_key` 后，正则规则都没
  匹配上时会再让 AI 解析一次意图（会增加调用成本与延迟，默认关闭）。

## 数据与持久化

| 内容 | 路径 |
|---|---|
| 配置 | `/data/config/config.yaml` |
| 小米登录凭据 | `/data/config/auth.json`、`/data/config/.mi.token` |
| 直连令牌 | `/data/config/.access_token` |
| 已处理消息去重时间戳 | `/data/config/last_timestamp.json` |
| 日志 | `/data/logs/bridge.log` |

升级附加组件不会删除以上文件。

写入方式：`auth.json` / `.mi.token` 先写私有临时文件（创建即 `0600`）再替换，
中途失败会回滚到旧凭据；`config.yaml` 和 `last_timestamp.json` 均使用临时文件、
`fsync` 与原子替换，降低断电留下半截文件的概率。两个凭据文件的替换不是跨文件原子事务：
如果异常断电造成身份不一致，桥接器启动时会拒绝混合登录并提示重新认证。

语音指令采用「**先记录时间戳、再执行动作**」的去重策略，优先避免重启后重复开关设备；
因此 HA 暂时无法执行时，这次语音指令不会被自动重新执行。如果去重文件损坏，桥接器会停止，
避免把旧语音当作新指令再次执行。请检查文件或从备份恢复，不要盲目删除。

### 这些数据会发往哪里

项目不会把数据上传到作者或第三方服务器，但运行中必然与下列服务通信：

| 数据 | 去向 | 什么时候 |
|---|---|---|
| 小米登录态（`passToken` / `serviceToken`） | 小米服务端（`account.xiaomi.com`、`*.mina.mi.com`） | 登录、刷新 Token、拉取设备与对话记录时；这是控制小爱音箱的前提 |
| Home Assistant 长期访问令牌 | 你填写的 HA 地址 | 调用 HA 服务、读取实体列表时 |
| 语音文本 | 小米（对话记录）与本机 | 轮询对话记录时；如果在「高级设置」启用「AI 托管」，还会发给你配置的 AI 接口 |
| 配置与规则 | 只留在 `/data` | 不上传 |

注意：`/data` 会随 Home Assistant 备份一起备份，**备份文件里包含上述凭据**，请妥善保管；
怀疑泄露时用「清除登录凭据」重建小米登录、删除 `.access_token` 轮换直连令牌。

## 常见问题

**Q：侧边栏看不到面板？**
确认加载项已启动；设置 → 加载项 → XiaoAI HA Bridge → 打开「显示在侧边栏」。
面板只对 Home Assistant 管理员显示。

**Q：面板打开是空白/一直转圈？**
先看 **实时日志** 页。若日志里出现「收到 Ingress 请求但来源 … 不是 Supervisor(172.30.32.2)，
已拒绝」，说明请求没有经过 Supervisor 代理（常见于自定义反代/端口直连），请改用侧边栏入口。

**Q：直连端口打开后要令牌，令牌在哪？**
面板 → **高级设置** → **显示直连令牌**。日志里只有文件路径，没有令牌本身（1.0.10 起）。

**Q：对小爱说话没反应？**
按两步判断：

1. **仪表盘的「最近」有没有出现新的语音？**
   - 没有 → 先看面板顶部的红字提示：
     - 「小米登录已过期，正在自动重试」→ 网络/STS 抖动，会按 10→300 秒退避自愈，等一会儿；
     - 「小米登录凭据已失效（code=…）」→ 小米已经拒绝这份 `passToken`，重试不会恢复，
       请到「小米账号」页**重新扫码登录**（重新登录后桥接器会自动重试，不必等退避走完）；
     - 没有任何提示 → 重启桥接器让它重新换票。
   - 有 → 看第 2 步。
2. **「指令执行」计数有没有增加？**
   - 没增加 → 规则没匹配上，或实体 ID 写错；用规则页测试区验证。
   - 增加了但设备没动 → Home Assistant 里该服务/实体的权限或名称问题，去 HA 日志看。

**Q：可以用账号密码登录吗？**
可以。1.0.12 起「账号密码登录」卡片直接支持：填账号密码 → 点「登录」。小米要求二次验证时，
验证码面板会出现在同一张卡片里：点「获取验证码」→ 输入验证码 → 点「提交验证码」。
> 该流程目前只通过模拟回归测试，**真实小米账号兼容性仍待验证**；卡住时请改用扫码登录。
> 邮箱验证码（小米返回 `flag=8`）本版本只识别、不发送，会提示改用扫码登录。

失败时的行为（都是安全的，不会破坏已有登录）：

- 提示「验证会话已失效」→ 验证会话 5 分钟过期，点「重新开始」后重新登录；
- 提示「验证码不正确（还可尝试 N 次）」→ 输错会累计，连续 5 次需要重新登录；
- 提示缺少 `serviceToken` / `passToken` → 小米没有返回可用凭据，**不会写入任何文件**，
  旧凭据原样保留；
- 提示设备列表获取失败 → 凭据未通过校验，同样不会落盘，可重试。

**Q：Cookie 登录怎么用？**
展开「高级选项：手动 Cookie 登录」，粘贴包含 `userId` 与 `passToken` 的浏览器 Cookie
（已登录 `account.xiaomi.com` 时从 F12 → Application → Cookies 复制），点「验证 Cookie」。
只有 `userId`/`passToken` 时插件会自动换取 serviceToken；换取或设备校验失败都会给出明确错误，
且不会写入任何文件。

**Q：粘贴浏览器跳转地址还行吗？**
只作为「兼容」子块保留在高级选项里。该地址与**浏览器会话**绑定（验证 Cookie 在浏览器里），
插件会话通常无法复用，所以常见结果是 HTTP 401；这不是「链接过期」，而是机制上不支持。
建议改用账号密码登录或扫码登录。

**Q：换一台小爱音箱 / 多台音箱？**
登录后会在设备列表里发现全部音箱；语音指令按各自设备的对话记录轮询，规则对所有设备生效。

**Q：直连端口安全吗？**
明文 HTTP，只建议可信局域网。它的价值是 Ingress 异常时的备用入口，日常请走侧边栏面板。

**Q：日志在哪？怎么反馈问题？**
界面 **实时日志** 页可看最近 80 条；完整日志在 `/data/logs/bridge.log`。反馈问题时请附：
加载项版本、HA 版本、日志片段（**请先删掉 Cookie/令牌**）、复现步骤。

## 清除已保存的小米登录

小米账号页的 **🗑 清除登录凭据** 会删除 `auth.json`、`.mi.token` 以及配置里的 Cookie / 密码，
并停止桥接器。之后需要重新登录（扫码 / 账号密码 / Cookie 任选）。**此操作不可撤销**。

## 升级前备份与回退

> **验证边界**：`/data` 的升级与回退兼容性是用**真实补丁代码**跑过的（1.0.9 → 1.0.10 →
> 再退回 1.0.9，见仓库里的 `test_upgrade_data.py`）。但**加载项安装器本身**（Supervisor 拉镜像、
> 创建 Ingress 面板、快照/还原）无法在 CI 里验证，必须在一台真实 HAOS 上人工确认一次。

1. 界面里 **导出** 当前意图规则；再在 设置 → 系统 → 备份 里做一次完整备份。
2. 记下当前登录方式（扫码 / Cookie），升级后如需重登，重新扫码即可，规则不用重配。
3. 升级后逐项确认：
   - **侧边栏面板**：设置 → 加载项 → XiaoAI HA Bridge → 打开，能看到状态/规则/设备；
   - **直连旧入口**：`http://<主机IP>:47521` 显示登录页，粘贴「高级」页里的令牌可进；
   - **规则未丢**：规则页能看到原有规则与多实体选择；
   - **语音链路**：说一条已有规则，确认**下一条**指令即时生效（不需要重新登录小米）；
   - **定时任务**：定时任务页仍能看到 `xiaoai_bridge_*` 自动化。
4. **回退**（任一步失败就回退）——注意 **HAOS 加载项商店不列出历史版本**，所以只能这样回退：
   - **首选：从备份还原**。设置 → 系统 → 备份 → 选升级前那份 → **部分还原** → 只勾选
     XiaoAI HA Bridge（含其数据）。还原后加载项回到旧版本，镜像标签仍然存在，可以正常拉取。
     代价：`/data` 会回到备份时刻（会丢掉这期间的去重时间戳等）。
   - **只想回退代码、保留当前 `/data`**：手工 `docker pull ghcr.io/tarynwyj/xiaoai-ha-bridge-haos:<旧版本>`
     后让商店指向它（高级操作，不推荐）；或临时把本地仓库 `config.yaml` 版本改回旧版本再安装。
   - `/data` 无需手工清理：1.0.10 只新增了 `.access_token`；1.0.11 / 1.0.12 只改登录流程，
